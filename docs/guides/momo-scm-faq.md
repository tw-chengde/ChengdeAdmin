## 一、一般問題

### Q1: 串接 API 回傳「查無此供應商」訊息？
**A:** 請確認 `entpCode` 欄位填入廠編（6 碼），`entpID` 欄位填入統編（8 碼）。

### Q2: 請問 API `otpBackNo` 欄位要填寫什麼？
**A:** `otpBackNo` 為 C1209 OTP 序號後三碼。

### Q3: 請問 MD 的聯繫方式？
**A:** 可至 SCM 後台登入後，點擊右上角「聯絡窗口」查詢。

## 二、商品問題

### Q1: 商品暫存編號 (`supGoodsCode`) 與商品編號 (`goodsCode`) 有什麼差別？
**A:** 商品審核通過後才會產生商品編號（正式品號）。

### Q2: 商品內容異動申請後 momo 需要審核才會更新嗎？
**A:** 是的，商品異動需經 momo MD 審核通過後更新。

### Q3: 票券使用起訖日有變動該如何異動，是否需要特別通知 momo？
**A:** 如有需要，請向 MD 確認。

### Q4: 商品大圖要放在哪個 API 欄位？
**A:** 使用 Multipart 方式上傳，並將商品圖放在 `zip_file`。`zip_file` 最大可至 400MB。

### Q5: 步驟參數 (`doAction`) 的「暫存」跟「送審」差別是什麼？
**A:** 暫存是之後還可以進行修改；送審後就不能再修改。

### Q6: 檔案內容 (`zipFileData`) 可以放什麼內容的檔案？
**A:** 商品的相關圖檔。各個圖檔的命名規則請見《SCM_商品規格API-(十四)、商品圖檔命名(範例)》。

### Q7: 商品編碼 (`batchSupNo`) 是什麼？需要填什麼樣的資料？
**A:** 商品編碼會對應到上傳的圖檔名稱，建議使用英文大小寫、數字且為唯一值。

### Q8: 品牌代碼 (`webBrandNo`) 是所有電子票券的品牌都會有？會不會有查詢不到的情況？那還需要填寫嗎？
**A:** 可至 SCM 後台 D1102 功能查詢。若不確定要填什麼品牌代碼，請向 MD 確認。

### Q9: 電子票券也需填寫來源 (`goodsType`)、配送溫層 (`temperatureType`)、產地編碼 (`originCode`)、長寬高重量？
**A:** 
- 長、寬、高、重量請都填 `1`
- 配送溫層 (`temperatureType`)：請依商品溫層填寫（常溫填常溫代碼）
- 來源 (`goodsType`)：請依來源填寫代碼（原廠填 `01`）
- 產地編碼 (`originCode`)：請依產地填寫代碼（台灣填 `0886`）

### Q10: 銷售單位別 (`saleUnit`) 是指什麼？
**A:** 電子票券商品請填「無」，其他商品請依實際銷售單位填寫。

### Q11: 銷售注意事項 (`saleNotice`) 會顯示在商品頁面的哪個位置？
**A:** 僅供 momo 內部人員參考，不會在網頁顯示。

### Q12: 詳細介紹內文 (`detailInfo`) 裡包含的圖片是否需要上傳到 momo 才能使用？
**A:** 是，圖片需上傳至 momo。

### Q13: 票券兌換起訖日是否為優惠起日 (`etkPromoSdate`) 與優惠訖日 (`etkPromoEdate`)？若否，則需要放在 API 哪個欄位？
**A:** 是，但是 momo 對這 2 個欄位的定義如下：
- 不在優惠起迄日範圍使用的票券則當成現金券使用，需補原售價之差價。
- **範例**：若有一商品原價 $150，購買票價的價錢為 $100，於優惠起迄日期內購買的價錢為 $100。若於優惠起迄日之外使用，需自行貼補差價 $50。

### Q14: 網頁商品說明與欄位對應（例如品名與備註欄位）？
**A:**
- `supGoodsName_salePoint`：上極鍋物 2 人美國雪花牛吃到飽+無酒精飲料暢飲
- `supGoodsName_serial`：即買即用

### Q15: 分店編號 (`branchSn`) 的 H1108 編碼對照表記載在哪？
**A:** 可至 SCM 後台 H1108 分店管理功能查詢對照。

### Q16: 分店資訊（電話、地址、官網等等）有 API 欄位可以放嗎？
**A:** API 並無提供上述欄位。若有需要異動分店資訊，請至 SCM 後台 H1108 分店管理功能進行編輯。

### Q17: 庫存是放在可備貨量 (`prepareQty`) 欄位嗎？
**A:** 是。

### Q18: 商品新增成功後會回傳 momo 對應的商品編號嗎？還是必須由 `queryGoodsList` 再查回 momo 的商品編號？
**A:** 不會回傳。建議在建立商品時帶入原廠編號 (`entpGoodsNo`)，再使用 `queryGoodsList` 查詢。

### Q19: 登入日期 (`frDate`) 是指什麼的登入日期？
**A:** 登入日期 (`frDate`) 為新增商品的日期。

### Q20: 商品庫存量是查詢可備貨量 (`prepareQty`) 嗎？
**A:** 商品庫存請使用「商品加減量查詢 API」的「可接單量 (`ORDER_COUNSEL_QTY`)」。

### Q21: 單品編號 (`goodsdtCode`)、單品詳細 (`goodsdtInfo`) 是什麼？
**A:** 先使用「商品上下架-查詢 API」取得單品編號 (`goodsdtCode`) 及單品詳細 (`goodsdtInfo`)，然後再使用「商品上下架-上下架申請 API」將值帶入。

## 三、訂單問題

### Q1: AES 解密問題：請問是使用 AES 的什麼模式？Key 與 IV 的值是什麼？
**A:** 
- 回傳資料為經過 AES 加密之字串。
- **Key (金鑰)**：SCM 主帳號 (`master`) 補 `0` 至 16 位數（例如：密碼為 `abcd1234`，金鑰為 `abcd123400000000`；以 GIO 為例，Key 值為 `shop7976000000`）。
- **解密流程**：先進行 Base64 解碼，再進行 AES (ECB 解密模式) 解碼。
- **IV**：為 `0` 即可。
- **適用 API**：《SCM_訂單API規格文件_V3.1》中第 (一)、(十三)、(十五) 支 API 有使用加密。

### Q2: 取消與退貨的定義為何？
**A:** 
- **取消**：系統未核單、還未通知廠商出貨前，判定為取消。
- **退貨**：系統核單後、通知廠商出貨後，消費者退貨/取消皆視為退貨。

### Q3: 出貨前進行取消或退貨該如何處理與辨識？
- **1-1. 未出貨訂單-廠商配送-查詢 API**
- **1-2. 未出貨訂單-超商取貨-查詢 API**
- **A:**
  - 出貨前進行取消：不會通知供應商。
  - 出貨前進行退貨：可至「未押出客辦退」功能進行查詢。

### Q4: 「未回收訂單-廠商配送-查詢」此 API 是否為消費者在網站上進行退貨申請？
**A:** 沒錯。

### Q5: 「未回收訂單-超取客未取確認-查詢」此 API 是否為消費者在網站上進行退貨申請？
**A:** 消費者在網站上進行退貨申請分為兩種狀況：
1. **消費者未取貨**：可於「未回收訂單-超取客未取查詢」辦理。
2. **消費者已取貨後辦理退貨**：
   - 有合作第三方物流：使用「未回收訂單-第三方物流回押回收確認-查詢」
   - 無合作第三方物流：使用「未回收廠配-查詢」

### Q6: 「未回收訂單-廠商配送-查詢 (`recoverCompanyQuery`)」轉單日是指訂單時間還是顧客按退貨的時間？
**A:** 不是，指 momo 通知供應商進行回收處理的時間。

### Q7: 出貨確認時 `sendInfoList` 傳入多筆資料，若其中一筆失敗，其他訂單會正常發貨還是整體失敗？
**A:** 其他訂單會正常發貨。

### Q8: 請問未出貨訂單系統轉單時間？
**A:** 甲配訂單系統於每分鐘執行轉單作業。

### Q9: 一個訂單行包含多件商品，我們可以對訂單進行拆包裹發貨嗎？
**A:** 可以。超取和第三方訂單可以執行系統併箱。以超取訂單為例，在使用「未出貨訂單-超商取貨-併箱 (`unsendStoresCombineBox`)」API 時，可依照需求選擇併箱出貨或分箱出貨。
